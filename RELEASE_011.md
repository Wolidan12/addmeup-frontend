## New database stage 011

`admin_bulk_create_managed_profiles(p_batch uuid, p_rows jsonb, p_reason text, p_confirm boolean)` creates 1–25 managed listings atomically, at most 512 KB per request. It requires a trusted super-admin role, explicit confirmation and an audit reason. It strictly validates names, usernames, interests, portrait/social URLs, visibility and duplicates. A failed item rolls back the whole batch. A stable batch UUID binds the actor, exact payload hash and reason; replay returns the original IDs instead of creating duplicates. Batch records are inaccessible to browser roles; validation helpers are not browser-executable. Profile mutations continue through existing trusted admin functions and append-only auditing. No Supabase Auth users, emails or passwords are created.

The studio defaults listings to private, supports individual portrait uploads, reviews visibility before confirmation, preserves the batch UUID after ambiguous errors and locks editing once a submission might have committed. Images use the existing managed-avatars storage authorization. Uploads happen before the atomic database transaction: cancelling or validation failure may leave an unused uploaded image; automatic orphan cleanup is not implemented. Facebook aliases are normalized to canonical `facebook.com` links on the client, keeping the bulk and existing single-edit database validation consistent.
